1. DESCRIPCIÓN GENERAL DE LA PERSISTENCIA Y ARQUITECTURA WEB
--------------------------------------------------------------------
Para la persistencia se utiliza PostgreSQL junto con la herramienta sqlc, generando código Go nativo y fuertemente tipado a partir de esquemas y consultas SQL estándar. 

Además, en este proyecto se integra una arquitectura web modular basada en componentes UI con 'templ' y controladores HTTP en un paquete dedicado ('handlers'), exponiendo rutas para gestionar el registro de usuarios, manejo de sesiones por cookies, gestión de categorías y el CRUD completo de destinos turísticos con soporte de búsqueda. La aplicación conecta la capa web directamente con la capa de datos generada por sqlc respetando restricciones de claves foráneas.

La conexión y ejecución en Go se gestiona mediante la interfaz nativa 'database/sql' asistida por el driver físico de PostgreSQL 'github.com/lib/pq', encapsulada en un módulo de conexión dedicado ('db/connect.go').


2. ESTRUCTURA Y EXPLICACIÓN DE ARCHIVOS
--------------------------------------------------------------------

- db/schema/schema.sql
  Define la estructura de las tablas relacionales en la base de datos PostgreSQL:
  - Tabla 'usuarios': almacena la información de los usuarios registrados.
    - id: identificador numérico autoincremental (PRIMARY KEY).
    - nombre: texto con el nombre del usuario (NOT NULL).
    - email: correo electrónico único (UNIQUE NOT NULL).
    - created_at: marca temporal de creación.
  - Tabla 'categorias': define las categorías clasificatorias de viajes.
    - id: identificador numérico autoincremental (PRIMARY KEY).
    - nombre: nombre único de la categoría (UNIQUE NOT NULL).
  - Tabla 'destinos': almacena información de viajes relacionada con usuarios y categorías.
    - id: identificador numérico autoincremental (PRIMARY KEY).
    - nombre_lugar: texto con el destino turístico (NOT NULL).
    - fecha_viaje: marca temporal de la fecha de visita (NOT NULL).
    - valoracion: puntuación numérica entre 1 y 10 (admite nulos).
    - descripcion: detalle opcional (admite nulos).
    - categoria_id: clave foránea referenciando a categorias(id) ON DELETE SET NULL.
    - usuario_id: clave foránea referenciando a usuarios(id) ON DELETE CASCADE.
    - created_at: marca temporal de creación.

- db/queries/users.sql (o archivos de consultas sqlc)
  Contiene las consultas SQL puras con anotaciones de sqlc para las tres entidades:
  - CreateUsuario, GetUsuario, ListUsuarios, UpdateUsuario, DeleteUsuario, GetUsuarioByEmail.
  - CreateCategoria, GetCategoria, ListCategorias, UpdateCategoria, DeleteCategoria.
  - CreateDestino, GetDestino, ListDestinos, UpdateDestino, DeleteDestino, SearchDestinosByLugar.

- sqlc.yaml
  Archivo de configuración de sqlc. Define el motor de base de datos (postgresql), dónde leer el esquema, las queries y la ruta del paquete destino para el código generado en Go (db/sqlc).

- db/sqlc/* (Generado por sqlc: models.go, db.go, users.sql.go)
  Contiene el código Go fuertemente tipado para interactuar con la base de datos, manejando tipos anulables ('sql.NullInt32', 'sql.NullString') y propagación de contextos.

- db/connect.go
  Módulo encargado de centralizar la apertura de la conexión a la base de datos PostgreSQL mediante 'sql.Open' y verificación con 'Ping', leyendo las variables de entorno de configuración.

- handlers/handler.go
  Controlador modular de la aplicación web:
  - Gestiona la autenticación de usuarios basada en cookies ('user_id') mediante 'getLoggedUser', 'HandleLogin' y 'HandleLogout'.
  - Orquesta la vista principal ('HandleIndex') soportando filtros de búsqueda por lugar ('SearchDestinosByLugar') y listados separados de reseñas del usuario autenticado.
  - Implementa los manejadores para procesar formularios HTTP de creación y eliminación de destinos, usuarios y categorías.

- views/*.templ (Plantillas Templ)
  Define la interfaz de usuario en componentes Go fuertemente tipados utilizando la librería Templ y estilos con Pico.css:
  - Layout.templ: estructura HTML base con soporte para barra de navegación, formularios de inicio de sesión y renderizado condicional.
  - EntityForm.templ: formularios dinámicos para registro de usuarios, creación de reseñas y categorías.
  - EntityList.templ: tablas interactivas para visualizar los destinos, filtrar por lugar y gestionar las reseñas propias con opción de eliminación.

- main.go
  Punto de entrada de la aplicación web y servidor HTTP:
  - Conecta a la base de datos utilizando 'db.ConnectDB()'.
  - Instancia las consultas de sqlc e inicializa el enrutador de controladores ('handlers.NewServerHandler').
  - Configura los archivos estáticos y registra las rutas HTTP del multiplexor estándar ('http.HandleFunc') para la página principal, sesiones, destinos, usuarios y categorías.

- .env y .env.example
  - .env.example: plantilla que define las variables de entorno necesarias (host, puerto, usuario, contraseña, base de datos).
  - .env: archivo de configuración local generado automáticamente por el Makefile a partir de la plantilla.

- Makefile
  Automatiza el ciclo de vida del entorno, la creación del archivo de configuración '.env', la compilación y la ejecución de la API mediante contenedores Docker:
  - .env: regla automática que clona '.env.example' si no existe.
  - generate: ejecuta 'sqlc generate' y la compilación de plantillas con 'templ generate' asegurando la actualización del código.
  - build: compila la aplicación Go dentro de la carpeta temporal 'tmp/'.
  - db-up: limpia contenedores previos, levanta un contenedor PostgreSQL temporal en segundo plano, espera que acepte conexiones con 'pg_isready' y aplica el esquema.
  - db-down: detiene y borra el contenedor junto con sus volúmenes asociados.
  - run-app: levanta la base de datos de manera automatizada con Docker, compila el binario y ejecuta el servidor web en http://localhost:8080, asegurando la limpieza automática mediante 'db-down' al finalizar.
  - clean: limpia volúmenes y la carpeta temporal 'tmp'.


3. CONCEPTOS Y HERRAMIENTAS CLAVE UTILIZADAS
--------------------------------------------------------------------

- database/sql vs github.com/lib/pq:
  'database/sql' es la interfaz genérica de Go para bases de datos relacionales, mientras que '_ "github.com/lib/pq"' registra internamente el driver físico para PostgreSQL.

- Automatización de Variables de Entorno (.env):
  Se implementó una regla en el Makefile para asegurar la creación automática del archivo '.env' a partir de '.env.example', cumpliendo con los estándares de entrega y buenas prácticas de configuración.

- Manejo de valores anulables con sql.Null*:
  Los tipos 'sql.NullInt32' y 'sql.NullString' encapsulan los datos opcionales de la base de datos junto con una bandera booleana 'Valid' para manejar de forma segura los valores NULL en la API y las consultas de sqlc.

- Arquitectura de Componentes con Templ y Handlers:
  Separación limpia de responsabilidades mediante la división en paquetes ('db', 'handlers', 'views'), utilizando plantillas HTML tipadas con Templ y controladores HTTP robustos para una interfaz moderna y mantenible.
